Prove your own lemma

From a theorem statement to a kernel-checked proof file, in four steps.

1. Set up once

Install Node.js 22 or later, Git and elan, then build the pinned Lean project. The Mathlib cache download saves you from compiling Mathlib yourself.

git clone https://github.com/allsmog/Formal-Verify-Anything.git
cd Formal-Verify-Anything
npm ci --prefix formal
lake exe cache get
lake build
node formal/src/cli.mjs doctor

doctor checks the installed Lean and Lake versions against the pinned toolchain and Mathlib commit.

2. Write the theorem as a manifest

Save a JSON file with the complete declaration up to its type, without := by or a proof. The id must match the theorem name.

{
  "id": "my_conjunction",
  "statement": "theorem my_conjunction (P Q : Prop) (hP : P) (hQ : Q) : P ∧ Q",
  "imports": ["Mathlib"],
  "opens": []
}

Imports are limited to the pinned Mathlib, Std and Init. A file can hold one problem, an array of problems, or an object with a problems array. Whitespace in the statement matters if you also supply a statementHash.

3. Run the search

node formal/src/cli.mjs solve my-lemma.json --out .fva/my-lemma

The output directory must be new or empty, so earlier evidence is never overwritten. It receives a JSON summary, the accepted proof if one was found, and result.json with the full proof tree, every attempt and every diagnostic. Progress prints to standard error.

The default proposer is deterministic and makes no model calls. To let an agent propose steps, add --proposer codex; see using it with your agent. Add --compiler worker to keep Mathlib loaded between exploration calls. Limits such as --max-compiler-calls, --max-depth and --timeout-ms are recorded in every result.

4. Verify the proof on its own

node formal/src/cli.mjs verify my-lemma.json \
  .fva/my-lemma/my_conjunction.lean --id my_conjunction

Verification needs the original manifest, so it cannot quietly swap in a different statement. It copies the proof to a read-only snapshot, compiles it with the pinned project, and reports VERIFIED only when Lean exits cleanly and the kernel audit of the theorem passes. Exit code 0 means success, 1 a failed proof or check, and 2 malformed input.

If the search fails

A failed search is a failure of that bounded attempt, not evidence that the theorem is false. Open result.json to see where branches were pruned and what Lean said, then try a larger budget, the persistent worker, or an agent proposer.
