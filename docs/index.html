The loop

Every theorem goes through the same bounded loop. The agent never gets the final word.

  1. Lean reports the goal. The runner locks the original statement and asks Lean for the current target, hypotheses and goal structure.
  2. An agent proposes a step. The Codex CLI, your own model command, or a deterministic tactic policy suggests a tactic, a case split, or a have sublemma, seeing only the local goal and its own recent compiler feedback.
  3. Lean checks it. Each branch is replayed in a fresh file with the original theorem. A failed branch rolls back to the exact parent plan and the search tries something else, within shared limits on compiler calls, depth, tokens and time.
  4. The kernel decides. A proof is accepted only after two fresh standalone compilations and an audit of every transitive dependency. sorry, new axioms and trust shortcuts are rejected; only propext, Classical.choice and Quot.sound are allowed.

Quick start

You need Node.js 22 or later, Git and elan. The repository pins Lean 4.24.0 and an exact Mathlib commit, and the runtime has no npm dependencies.

git clone https://github.com/allsmog/Formal-Verify-Anything.git
cd Formal-Verify-Anything
npm ci --prefix formal
lake exe cache get
lake build
node formal/src/cli.mjs doctor
node formal/src/cli.mjs solve benchmarks/tier1.json --id conjunction_commutation

The default solver makes no model calls. Add --proposer codex to let a Codex agent propose the steps; see using it with your agent.
